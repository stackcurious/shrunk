## Findings → what I did

### Blocker

**B3 — Dynamic Type breaks the core screen.** Fixed, and verified by capture.
- `ResultView.costPerOzSection`: the two cost rows were inside a `GeometryReader` pinned to
  `.frame(height: 64)`, so at AX5 the content grew past the frame and the percentage line was drawn
  over the bars. The `GeometryReader` is gone; each row is a self-sizing `VStack` whose label and
  figure share a line above a 22 pt bar, and only the bar's own width is measured.
- `ResultView.costBarRow`: `Text(label).frame(width: 40)` truncated `Then` to `…`. The fixed width
  is gone.
- `ResultView.quantityCell`: `.lineLimit(1).minimumScaleFactor(0.6)` truncated `946.4 ml` to
  `946.4…`. Now `.lineLimit(2)`, floor 0.5, `fixedSize` vertical.
- `ResultView.comparisonRow`: `AnyLayout` — `HStack` normally, `VStack` with `arrow.down` past
  `isAccessibilitySize`.
- `BrowseView.TrendingCard`: `.frame(width: 320, height: 132)` replaced by a `@ScaledMetric` width
  capped at 460 with an intrinsic height.
- Found while verifying, same blocker: `LivePricePanel`'s price/promo/stock row and its store-name
  header now wrap to a column at accessibility sizes; `ResultView`'s hero brand·category `HStack`
  became one `Text`; `ShrinkHistoryChart.beforeAfter` stacks the same way as the Then→Now row;
  `ShrinkMeter`'s centre labels are capped at `.accessibility1` because the ring is a fixed-diameter
  graphic (everything it says is in its uncapped accessibility label).

### Should-fix

**S1 — no navigation titles on the Result and Paywall sheets.** `ResultView` gets
`.navigationTitle(product.name)` (falling back to "Scan result"), `ProPaywallView` gets
`.navigationTitle("Shrunk Pro")`. Captured: shot 03 shows `Apple Cinnamon Cheerios` condensed in the
bar instead of the hero fading under an empty one.

**S2 — window scheme flipping on tab switch.** `MainTabsView.preferredColorScheme(selectedTab == 0 ? .dark : nil)`
deleted; the window stays in the user's appearance. `ScannerView`'s `.environment(\.colorScheme, .dark)`
moved *inside* its presentation modifiers so it dresses the camera chrome and no longer flows into
the Result sheet presented from it. `SystemAppearance` and `ResultView`'s
`.preferredColorScheme(SystemAppearance.current)` are both deleted. Verified by capture: the scanner
keeps a light status bar and a dark translucent tab bar, Browse renders in system light with a dark
status bar — no window-wide cross-fade between them.

**S3 — "Set your store in Settings" with a store set (Alternatives).** `emptyMessage` branches on
`storeName`: unset → the old copy; set → "No cheaper option at ‹store› right now. We'll keep
checking."

**S4 — same dead end on the savings dashboard.** The how-it-works rows take `done:`; step 1 ticks
green and reads "Store set — ‹store›" when a store is set, step 2 reads "Watching N products" when
the watchlist isn't empty.

**S5 — unknown stock rendered in the green in-stock capsule.** Test first
(`ShrunkTests/LivePriceStockTests.swift`, 4 cases). `StorePriced` gains a four-case `StockState`;
`inStock` is now HIGH-or-LOW only, and a new `isOutOfStock` is what `AlternativesEngine` filters on —
dropping every row with no stock field would have emptied the list on a store that doesn't report it.
`LivePricePanel` has a tri-state (plus neutral) pill; `AlternativeRow`'s stock mini-stat maps
"Stock unknown" to the neutral tone. Captured: the pill is grey, not green.

**S6 — `verdictWarn` at 2.17:1.** Light `EF9F27` → `B2700B` (4.0:1 on white — clears the 3:1 non-text
and large-text floors it is used for: alert glyph, meter numeral and ring, history bar).
`verdictWarnDeep` light `B2700B` → `8A5600` (6.2:1 on white, 5.5:1 on `verdictWarnTint` — clears AA
for body text). Dark values untouched. Verdict semantics unchanged.

**S7 — `.insufficientData` pill at 3.11:1.** `verdictTextColor` returns `Color(.label)` instead of
`.secondary` for that verdict.

**S8 — `.white` on a dynamic `verdictGood` (2.11:1 in dark).** New pinned `Color.verdictGoodSolid`
(`157852`, white on it 5.5:1 in both schemes) backs the alternatives "Best value" badge and the
paywall's "Save 58%".

**S9 — button labels truncate.** `ShrunkButton`: `.lineLimit(2)`, floor 0.6, centred.

**S10 — store picker's silent no-op.** Fixed at the source: `StorePickerViewModel.search()` no longer
returns silently when `canSearch` is false — it sets `.failed("Enter a 5-digit ZIP code.")`, which the
existing `.failed` section already renders. The picker also shows the store already chosen as a
checked "Your store" row. **Partial:** `.keyboardType(.numberPad)` — see "not fixed" below.

**S11 — unread `errorMessage`, unconditional success toast.** `toggleAlert` and `remove` return
`Bool`; `WatchlistView` toasts the success copy only on `true` and the view model's `errorMessage`
(with the error icon and red tint) otherwise.

**S12 — two silent Settings actions.** "Clear scan history" gets a confirmation dialog, a success
toast, and loses the chevron (new `showsDisclosure` on `SettingsRow`). Both "Restore purchases"
call sites now go through one `restoreButton` that reports through
`ProPaywallViewModel.restoreOutcomeMessage` — "Shrunk Pro restored." or the paywall's own failure copy.

**S13 — single-snapshot copy gated on the verdict.** `sizeFactLine` is gated on
`record.previousSize == nil`, and `comparisonRow` refuses to draw a Then→Now row for
`.insufficientData` — that verdict also comes out of `ShrinkDetector`'s zero-quantity guard and
plausibility clamp, both of which keep a `previousSize` we have decided not to trust (the zero case
would print "0 ml → 946.4 ml"). Those states fall through to the single "Current size" card.

**S14 — "354.369" on the confirm sheet.** `ContributeViewModel.format` rounds to 1 dp. The submitted
value is what the shopper confirmed, so `test_submit_sendsTheConfirmedValuesAndThePhoto` and
`test_format_…` were updated to 340.2 / 354.4. Captured in shot 04.

**S15 — fixed 420 pt confirm sheet.** `.presentationDetents([.medium, .large])`, and the sheet's body
is a `ScrollView` with `.scrollBounceBehavior(.basedOnSize)` so Submit can never be clipped.

**S16 — accessibility gaps.** `WatchlistRow` combines its children, takes `.isButton` and a default
action. `ShrinkMeter` is one element with a spoken verdict ("Shrunk 12.5 percent"). History bars carry
`shrank` / `held its size` / `grew` as an `accessibilityValue`, from a single `change(at:in:)` the bar
colour also reads, so the two channels can't disagree.

### Nits

**N1 — the gauge contradicts its numeral.** `targetFillFraction` is now `abs(percentChange) / 100`
for every change verdict: the arc *is* the percentage, so 12 % draws a 12 % arc. Was 25 % / 30 %
full-scale, which drew a half-full ring around "12%".

**N2 — not-found headline.** Restored to §2's "Not in our database yet"; the duplicate "Close"
button removed (the toolbar ✕ is right there).

**N3 — scanner.** Recent chips get `.contentMargins(.horizontal, 16, for: .scrollContent)` plus a
trailing gradient mask, so the row reads as scrollable rather than truncated (verified by capture).
The reticle is one stroke plus the corner brackets; the breathing outer ring and its `pulseOuter`
state are gone.

**N4 — Share in the single-snapshot state.** Gated on `previousSize != nil`, which is both what §2's
table lists and the only thing `ShareCardView`'s Then→Now block can draw.

**N5 — 🔒 PRO.** The `.pill` style drops the padlock.

**N6 — dead code.** `ProductThumb.swift` and `StatBox.swift` deleted; `StatBoxTone` moved next to
`AlternativeRow`, its only remaining user, and its unused `.muted` case dropped.
(`ShrunkButtonVariant.destructive`/`.secondary`, `ProBadge.Style.lock`/`.ribbon` and
`ShrinkMeter.Size.mini` are left alone — the review's suggested fix named only the two files and the
struct, and the enum cases are cheap, referenced by previews, and not a correctness issue.)

**N7 — double Kroger attribution.** `LivePricePanel` prints it only in the `.loaded` branch (a
spinner or an "unavailable" card has no Kroger data to attribute), and the per-ounce card suppresses
its own copy when the store card below is carrying it. Captured: exactly one on shot 03.

## Not fixed — one line each

- **B1, B2** — data/deploy findings owned by another agent (feed contents, the Toblerone alerts
  fixture, the stale `05_alerts.png`). Not touched, as instructed.
- **N8** (`ScreenshotTests.swift:186` → `.firstMatch`) — that file is another agent's and currently
  dirty, so I left it alone. The finding is moot in practice: N7 means "Prices from Kroger" now
  matches exactly one element on shot 03's screen, and the suite passes.
- **S10, keyboard type only** — `.searchable` has no API for `keyboardType` on iOS 17/18 (the
  embedded picker's own `TextField` already has `.numberPad`), and spec §3 pins the store picker to
  a `.searchable` list. The substance of S10 — the silent no-op and the invisible current store —
  is fixed; a numeric keypad there needs either a `UISearchBar` appearance-proxy hack or dropping
  `.searchable`, and neither is worth it without a spec amendment.
