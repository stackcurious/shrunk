## 2026-08-27 — separators in the shared normalizer (R47/R48)
- `,` `/` `()` on a package label all mean "the same quantity, said again" — never addition. The normalizer split on `/` and `()` but not `,`, so `"14.5 oz, 450 g"` fell into the compound-imperial ("1 lb 4 oz") branch and returned 861 g: roughly double the truth, which reads as a fabricated shrink on the next observation. Rule: when adding a separator, add it to *all three* implementations' segment split in the same commit, and check what the string does in the additive branch before assuming a miss — a wrong size is worse than none, and only the fixture can prove which one you got. The same audit found `"8.8/249 g"` recorded as 2191 g (a decimal read as a pack count) and `"6 1/2 oz"` as 2 oz (a mixed number split into "6 1" + "2 oz") — 25 production rows in all, invisible until the raw text was re-parsed and diffed against what was stored.

## 2026-08-27 — the curated catalogue was authored from invented data (curated-audit)

## 2026-08-27/28 — the citations were invented too (curated re-verification)

- `612cc40` fixed the fabricated *barcodes*. It did not touch the *claims*, and the follow-up found the rest of the same rot: **all 35 `evidence_url`s returned 404** (33 distinct mouseprint.org / consumerreports.org / bbc.com paths, every one invented, while `mouseprint.org` itself returns 200), and the before/after size pairs behind them had never been checked against anything either. Only **17 of 35** had a real documented counterpart — and most of those had the wrong numbers, wrong dates, or the wrong product variant (there is no 13.5 oz Wheat Thins box; the real case is 16 → 14 oz. There is no 19 oz Cheez-It. Hellmann's was recorded as mass when it is a fluid measure). 18 had no source at all. Final catalogue: 25.
- **Rule: an `evidence_url` is not evidence until it has been fetched.** `curl -s -o /dev/null -w "%{http_code}"` on every citation, and the page must contain a sentence naming *both* sizes for *that* product. A percentage ("10% fewer tissues"), a "lost two ounces", or a figure that appears only in a headline or an image is not a source. Put the quote in the review, capped at ~15 words, so the check is auditable without re-fetching.
- **Rule: enumerate the corpus, don't search it.** Chasing 35 products through a search engine is 140 fetches and misses whatever the engine ranks low. Paging the archive index (`mouseprint.org/category/downsiz/` pages 1-44 → 120 article URLs), downloading all of it once and grepping locally cost ~130 fetches total, covered 2006-2026 exhaustively, and made per-entry verification free. It also surfaced the replacements. Do this for any "verify N things against one publication" task.
- **Rule for a GTIN carrying a historical size claim**: the current package must not be *larger* than the claimed after-size. Equal = the database confirms it. Smaller = it shrank again, and the entry still records the documented step. Larger = the claim is contradicted, and no amount of good sourcing rescues it — that is what killed Kleenex (110 claimed, 120 today) and Maxwell House (24.5 claimed, 27.5 today). Also check for *reversals*: Toblerone is the most famous shrinkflation case in the world and still had to go, because Mondelez reverted the 2016 gap-widening in 2018, so today's bar is not the shrunk one.
- **A metric that only passes on unverifiable data is measuring nothing — but its inverse is also a trap.** `hit_rate.py` now reads `shrink_detected=17/25`, and every one of the 8 misses is exactly `+0.0%`: USDA FDC reporting *precisely* the curated after-size, which flattens the last pair. That is confirmation, not contradiction (Fage independently confirms *both* endpoints and still scores "no shrink"). Before re-sourcing, the misses were real disagreements (+3.7%, +10.5%, +22.1%, +38.9%, +50.0%). Read the *shape* of a metric's failures before treating the number as a target: the underlying issue is that `ShrinkDetector.analyze`, `previousAcceptedQuantity` and `hit_rate.verdict` all compare the last two observations without collapsing consecutive within-tolerance sizes, so agreement from a second source reads as "unchanged" to the user. Do not "fix" the number by deleting the confirming rows.
- **When a data audit is running, grep the code for the data too.** Removing entries stranded three seeded UI-test fixtures and `ScreenshotTests.featuredBarcode`, all naming retracted products by brand — the same false claim, just in a screenshot instead of the feed. And the marketing site had copied the whole catalogue into a typed TS module plus "35 verified cases" in six places and a "Consumer Reports" provenance line for entries whose Consumer Reports link was a 404. A catalogue is never only in `data/`.
- **The audit that finds a fabricated claim should also look for the mechanism that publishes them.** `/v1/feed` was advertising OREO Double Stuf as "530 g → 31.5 g, **−94.1%**" because Kroger's own record gives that pack's size as "1.11 oz". `ShrinkDetector` already refuses cross-source pairs outside a 0.25-4 ratio; `buildFeed` had no such clamp, and it is the more consequential of the two — one renders a screen, the other publishes a claim to every Browse tab. Ported the clamp (`3eab74f`). Parity between a client-side sanity check and the server that feeds it is worth an explicit test.

## 2026-08-28 — a confirmation is not a change (size runs, spec §5.1)

- Verdicts were read off the **last two observations**, so a second source reporting *exactly* the size the previous observation already recorded produced `450 → 450`, `+0.0 %`, "Unchanged" — and erased the documented `500 → 450` behind it. Eight of the 25 verified curated entries scored "no shrink" that way; Fage was the proof, because USDA independently confirms *both* of its endpoints and the product still read as never having shrunk. Fixed by collapsing consecutive within-tolerance observations into **size runs** and comparing the last two runs, in all three implementations at once (`ShrinkDetector.collapseRuns`, `backend/src/runs.ts`, `hit_rate.collapse_runs`). `shrink_detected` went 17/25 → 25/25 without touching a byte of data.
- **Rule: when a rule says "the last two X", ask what a *repeat* of X does to it.** Any comparison of adjacent samples has this failure mode — corroboration is indistinguishable from stasis. Collapse equal-within-tolerance neighbours before selecting the pair, and compare each sample against the value that **opened** the run rather than its immediate predecessor, or a drift of sub-tolerance steps silently accumulates into one run spanning a real change.
- **Rule: verdict rules and event rules are not the same rule, and must not share an implementation by default.** "Is it smaller than it used to be" (Result screen, `/v1/feed`, hit rate) wants runs. "Did anything change since we last looked" (weekly digest, the Kroger sweep's `size_drop` alert) must *not* — collapsing there would re-report the same shrink in every digest and re-fire the same alert on every six-hourly sweep, forever. `previousAcceptedQuantity` and `runPairEndingAt` now sit side by side in `db.ts` with that distinction written into both docstrings.
- **A behaviour change deletes states as well as adding them.** Adjacent runs differ by more than the tolerance by construction, so `.unchanged` became unreachable from `analyze` — and the two-same-size-observations case that used to read "Same size since 2021" now falls into `.insufficientData`, which renders a *different* line ("946 ml, first seen …"). That line was being dated from the latest observation, i.e. from the confirmation. Grep the consumers of every field whose selection you change and read the copy they print, not just the types they compile against.
