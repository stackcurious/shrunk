
## 2026-08-26 — concurrent agents share one index
- When subagents commit concurrently on the same branch, never run a bare `git commit` in the controller; a subagent's staged change gets swept into the controller's commit (happened: UPCItemDBService.swift deletion landed in the phase-5 plan commit fc7f037). Always commit with an explicit pathspec: `git commit -m "…" -- <paths>`.
- Make subagents stage by path too (`git add <file>`), never `git add -A`.
- Reviewer subagents must be told explicitly "never `git stash`, `checkout`, or `reset`" — one stashed the worktree mid-review while another implementer had uncommitted work.
- Implementer reports sometimes paraphrase/estimate test counts. Dispatch prompts must say "paste the literal command output; never estimate", and reviewers should spot-check one count against the file.
- Implementers must commit with a pathspec too (`git commit -m "…" -- <files>`), not just stage by path — a bare `git commit` after `git add <paths>` still sweeps other agents' staged changes. Put this in every dispatch prompt.
- Implementers must never `git stash` either (one did, to isolate a failure, while another agent had uncommitted work).

## 2026-08-26 — simulator crash during a subagent test run
- The user surfaced a SIGABRT crash report from the simulator: a new XCTest force-cast a JSON request body (`as! [String: String]`) whose values were arrays/objects → `swift_dynamicCastFailure` aborts the whole test process, so the run ends with **no** `Executed … tests` line.
- Rule: briefs and dispatches say "never `as!` on decoded JSON in tests — `as? [String: Any]` and assert per key"; a report without a literal `Executed … tests` / `** TEST SUCCEEDED **` pair is a failed run, and the newest `~/Library/Logs/DiagnosticReports/Shrunk-*.ips` names the test (frame list of the faulting thread).

## 2026-08-27 — separators in the shared normalizer (R47/R48)
- `,` `/` `()` on a package label all mean "the same quantity, said again" — never addition. The normalizer split on `/` and `()` but not `,`, so `"14.5 oz, 450 g"` fell into the compound-imperial ("1 lb 4 oz") branch and returned 861 g: roughly double the truth, which reads as a fabricated shrink on the next observation. Rule: when adding a separator, add it to *all three* implementations' segment split in the same commit, and check what the string does in the additive branch before assuming a miss — a wrong size is worse than none, and only the fixture can prove which one you got. The same audit found `"8.8/249 g"` recorded as 2191 g (a decimal read as a pack count) and `"6 1/2 oz"` as 2 oz (a mixed number split into "6 1" + "2 oz") — 25 production rows in all, invisible until the raw text was re-parsed and diffed against what was stored.

## 2026-08-27 — the curated catalogue was authored from invented data (curated-audit)
- 34 of the 35 `barcode` values in `data/trending.json` were checksum-valid UPC-A codes that were never issued to those products: 32 returned `not_found` from Kroger product-by-id at a real store, 31 were 404 in Open Food Facts, and **none of the 35 appeared anywhere in the 377,782-row USDA FDC Branded import already sitting in D1**. Two resolved to *different* products (`0028400064057` → Tostitos Bite Size 13 oz, `0028400090094` → Lay's Salt & Vinegar 1 oz) and `KROGER_PERSIST="on"` had already written those foreign sizes into `observations` under our GTINs. Every one of the 33 distinct `evidence_url`s 404s while `mouseprint.org` itself returns 200 — the article paths were invented too. Rule: a valid check digit proves arithmetic, not existence. Before a barcode enters a shipped catalogue it must return a product from at least one product database (Kroger by-id, OFF, or FDC) and the returned brand/description must match the entry; the cheapest possible gate is `SELECT COUNT(*) FROM observations WHERE gtin = ?` against the FDC import we already have. Corollary: `hit_rate.py` read `shrink_detected=35/35` *because* the barcodes were fake — a GTIN no other database knows is a GTIN nothing can contradict. After correcting them, real USDA/Kroger rows landed on the same GTINs and disagreed with 10 of the 35 size histories (Wheat Thins has no 13.5 oz box, Cheez-It no 19 oz, Breyers no 32 fl oz…). A metric that only passes on unverifiable ids is measuring nothing.
