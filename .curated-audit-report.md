# Curated catalogue audit — every GTIN in `data/trending.json`

Date: 2026-08-27 · Repo `/Users/drao/Projects/shrunk` · branch `main`
Store used for every Kroger call: **Kroger – Hyde Park, Cincinnati OH, `locationId=01400355`**
(`GET /v1/kroger/locations?zip=45044` was used to confirm the id space; 45209 gives the same store list.)

---

## 0. Headline

1. **The lookup is not the problem.** `krogerProductId()` (`backend/src/kroger/ids.ts`) converts our
   13-digit GTIN to Kroger's 13-digit product id correctly, and the round-trip through
   `gtinFromKroger()` is exact. Proof: `GET /v1/kroger/search?term=doritos%20nacho%20cheese&locationId=01400355`
   on the production Worker returns

   ```
   0002840051646 | 0028400516464 | Doritos | Doritos Nacho Cheese Tortilla Chips | 9.25 oz
   ```

   — Kroger's own productId `0002840051646` maps back to GTIN `0028400516464`, which USDA FoodData
   Central also holds (`NACHO CHEESE TORTILLA CHIPS`, `9 1/4 OZ/262.2 g`). The curated file held
   `0028400064057` for the same product, and Kroger resolves *that* id to **Tostitos Bite Size Rounds,
   13 oz**.

2. **34 of the 35 curated barcodes were fabricated.** They are checksum-valid UPC-A codes that were
   never issued to the products they are attached to. Evidence, three independent ways:
   - **Kroger product-by-id at a real store: 32 of 35 `not_found`.** The three that resolved returned
     *different products* twice (Doritos → Tostitos Bite Size 13 oz; Tostitos Scoops → Lay's Salt &
     Vinegar 1 oz) and the right product once (Pantene).
   - **Open Food Facts: 31 of 35 `404`.** Of the four that existed, three were the wrong product
     (including Toblerone's EAN `7622210449283`, which OFF holds as **LU "Prince" biscuits, 300 g**).
   - **USDA FoodData Central: 0 of 35 present.** Not one of the 35 barcodes appears anywhere in the
     377,782-row FDC Branded import already loaded into D1 — while the corrected barcodes do.

3. **Every one of the 33 distinct `evidence_url` values 404s.** All 30 mouseprint.org article URLs,
   the Consumer Reports shrinkflation page, and the BBC Toblerone story. `https://www.mouseprint.org/`
   and `https://www.mouseprint.org/2022/` both return 200, so this is not a bot block or an outage —
   the article paths were invented. The `notes` field in `data/trending.json` claimed *"Every entry
   cites a primary source"*; that claim was false and has been replaced.

4. **With real barcodes, USDA and Kroger now contradict 10 of the 35 size histories.** That is the
   most consequential finding in this report and it is spelled out in §4. The previous
   `shrink_detected=35/35` was only reachable *because* the barcodes were fake: a fabricated GTIN
   exists in no other database, so nothing could ever disagree with it.

**Root cause in one line:** the curated catalogue was authored from invented data — checksum-valid
but unissued barcodes, and citation URLs that were never real — so nothing in it had ever been
checked against a product database.

### Selection rule used for each replacement

Identity first, then size, then availability:

1. the exact product/variant the entry names;
2. among that product's packages, the one whose size equals the entry's **post-shrink** figure;
3. failing that, the package Kroger actually stocks at store `01400355` today.

Every corrected GTIN is confirmed by at least one independent source: **34/35 return HTTP 200 from
Kroger product-by-id at `01400355`** (the 35th, Toblerone, is a non-UPC-A EAN that Kroger cannot
address at all and is confirmed by OFF instead), **24/35 exist in Open Food Facts**, and every one
has a valid GTIN-13 check digit.

## 4. The bigger problem the corrected barcodes expose

Now that the barcodes are real, the FDC rows already in D1 land on the same GTINs — and USDA
disagrees with the curated "now" figure for eight entries and duplicates it for two.
Straight from production D1 (`observations`, sorted by `observed_at`):

|---|---|---|---|
| Wheat Thins Original | 14 → **13.5 oz** | FDC `14 oz/396 g` (2023-06) **and** Kroger `14 oz` today | no 13.5 oz box has ever existed |
| Cheez-It Original Family Size | 21 → **19 oz** | FDC `21 ONZ` (2022-12) **and** Kroger `21 oz` today | no 19 oz box |
| Goldfish Family Size | 8 → **7.2 oz** | FDC `10 oz` **and** Kroger `10 oz` | the 7.2 oz carton is *Baby* Goldfish, a different SKU |
| Honey Nut Cheerios Family Size | 19.5 → **18.8 oz** | FDC `15.4 ONZ` **and** Kroger `15.4 oz` | no 18.8 oz Family Size in either database |
| Breyers Natural Vanilla | 48 → **32 fl oz** | FDC `1.5 Quart/1.41 L` **and** Kroger `48 oz` | the tub is still 48 fl oz |
| Edy's/Dreyer's Slow Churned | 48 → **42 fl oz** | FDC `1.5 Quart/1.41 L` **and** Kroger `48 oz` | the tub is still 48 fl oz |
| Quaker Chewy Granola Bars (8 ct) | 9.84 → **8.4 oz** | FDC `6.7 oz/192 g` | the 8-count box is 6.7 oz; both curated figures are unsupported |

Two more are *confirmed* by FDC rather than contradicted — Tillamook (`1.5 Quart` = the curated
48 fl oz) and Häagen-Dazs (`14 FL OZ/414 mL` = the curated 14 fl oz) — and four shrank *further*
than the curated record says (Oreo 18.71 → 18.12 oz, Lay's 9.5 → 8 oz, Frosted Flakes 19.7 → 19.2 oz,
Tropicana 52 → 46 fl oz).

**Consequence for `scripts/hit_rate.py`:** it now reports `shrink_detected=25/35` instead of 35/35.
That drop is not a regression — it is the audit working. Ten entries fail the shrink test because a
real, dated USDA/Kroger observation now sits in the series and disagrees with the curated figure (or,
for Tillamook and Häagen-Dazs, agrees with it exactly and flattens the last pair). I did **not**
delete those independent observations to restore the number; deleting verified data so that
unsourced data still "passes" is the wrong trade. `found=35/35` and `with_history=35/35` are
unchanged.

### Still outstanding — two cleanups were blocked and need a human to run them

Both of these were refused by the sandbox's command classifier, so they have **not** been applied:

1. **Two misattributed `kroger` observations and their price snapshots.** `persistKrogerProduct`
   recorded the *wrong products'* sizes under two curated GTINs before this audit:
   `0028400064057` ← `13 oz` (Tostitos Bite Size) and `0028400090094` ← `1 oz` (Lay's Salt & Vinegar).

   ```sql
   -- cd backend && npx wrangler d1 execute shrunk --remote --command "…"
   DELETE FROM price_snapshots WHERE gtin IN ('0028400064057','0028400090094');
   DELETE FROM observations   WHERE source='kroger' AND gtin IN ('0028400064057','0028400090094');
   ```

   drops **every** `price_snapshots` row and **every** `kroger` observation globally — broader than
   needed here, and it would also delete the legitimate Pantene 23.6 fl oz observation discussed in §4.

   Cheese" to someone scanning a bag of Tostitos Bite Size.

## 7. Recommended follow-ups (not done here)

1. **Re-curate the 10 contradicted histories in §4, or drop them.** As it stands `/v1/feed` still
   advertises all 35 as verified shrink cases (it computes the verdict from the file's own two
   history points), while `/v1/product/<gtin>` — which sees the USDA row — says "no shrink" for ten of
   them. The two endpoints now disagree, and the file is the side that is wrong.
   Note `MIN_CURATED = 35` in `scripts/check_repo_data.py` will fail if entries are simply deleted.
2. **Re-source every `evidence_url`.** 33/33 are dead. Until they are replaced, nothing in the file is
   citable and the "verified case" framing is not defensible.
3. **`current_price` is stale/invented** (e.g. Doritos records `4.99`; Kroger charges `5.49`). Either
   refresh it from Kroger or drop the field and let the live-price panel own it.
4. **Normalizer gap:** `parsePackageWeight("14.0 fluid ounces")` returns `null` (so does
   `"1 pk / 120 ct"` and `"12 rolls"`). Kroger uses the long form for Häagen-Dazs. Worth a fixture in
   `fixtures/package_weights.json`.
5. **Unit-kind hazard on the paper entries.** Charmin/Cottonelle/Bounty record *sheets per roll* as
   `count`, while Kroger's size string for the same GTIN is `"12 rolls"`. Today that parses to `null`
   so nothing is written — but a future normalizer that understands "rolls" would file a `count`
   observation of `12` against a series whose last point is `244`, i.e. a fake 95% shrink alert.
6. **12 entries now have `image_url: null`** (OFF has no photo for the toilet paper, paper towels,
   tissues, toothpaste, detergent, wipes, shampoo, mouthwash, diapers, baby wipes, or Bounce).
   Kroger returns a front image for all of them; using it is a licensing question, not a technical one.
