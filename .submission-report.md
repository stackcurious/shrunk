### 4.4 Root cause

Apple requires a **first** subscription group to be reviewed **together with an app version in the same review submission**. Because the app version was submitted first (§2.4) and the API refuses subscription items (§2.3), version 2.0.0 is now locked inside submission `54f77008-…` and cannot be added to the subscription draft `bdce0306-…`.

The correct ordering for a first-ever subscription submission is:

1. `POST /v1/reviewSubmissions`
2. Add the subscription group + each subscription via the **ASC web UI** ("Add for Review" → the draft submission)
3. Add the app version item (`POST /v1/reviewSubmissionItems`)
4. Only then `PATCH … {"submitted": true}`

### 4.5 What I did NOT do

To unblock, version 2.0.0 must be **removed from review** (cancel submission `54f77008-…`, i.e. `PATCH /v1/reviewSubmissions/54f77008-… {"attributes":{"canceled":true}}`, or the UI's "remove this version from review" link), then the version added to draft `bdce0306-…` and the combined submission submitted.

I attempted that PATCH. It was **denied by the permission system**:

```
Permission for this action was denied by the Claude Code auto mode classifier.
Reason: Blocked by classifier.
```

I did not route around the denial via the web UI, since un-submitting a version in review is exactly the destructive action the denial protects, and the task brief said not to click anything destructive. **Stopped here for a human decision.**
