# Backend: on-miss lookup keeps the size (spec §1 rule 6)

## Bug
`GET /v1/product/{gtin}` on-miss lookup (FDC → OFF) discarded the size string
(`packageWeight` / `quantity`), so a freshly-created product had zero
observations ("Not enough data yet" in the app).

## Files changed
- `backend/src/lookup/fdc.ts` — `FDCHit` gains `packageWeight`, `observedAt`
  (parsed from `publishedDate`/`modifiedDate`), `fdcId`.
- `backend/src/lookup/off.ts` — `OFFHit` gains `quantity`, `observedAt`
  (OFF's `last_modified_t`, already epoch seconds); requests those two extra
  fields.
- `backend/src/routes/product.ts` — `createFromLookups` now parses the raw
  size with the shared normalizer (`parsePackageWeight`) after the product
  row lands, and on success writes an accepted `observations` row (same
  insert path/columns other sources use, `status: "accepted"`,
  `confidence: 0.9` for `fdc` / `0.7` for `off`), and sets
  `products.unit_kind` when it was null (`setProductUnitKindIfMissing`).
  Wrapped in try/catch — a parse/insert failure never fails the product
  response, matching the spec's "best-effort" instruction.
- `backend/migrations/0007_observations_off_source.sql` — **new**.
  `observations.source` had a `CHECK (source IN ('fdc','curated','crowd','kroger'))`
  from `0001_init.sql` with no `'off'`. Production D1 already has data (spec
  §0: 371,400 products), so this couldn't be an in-place edit of an
  already-applied migration the way 0002–0006 were pre-launch. SQLite has no
  `ALTER TABLE ... ALTER CHECK`, so this is the standard rebuild: new table
  with the widened CHECK (`'fdc','off','curated','crowd','kroger'`), copy
  every row, drop, rename, recreate both indexes (`obs_gtin`,
  `obs_source_ref`).
- `backend/test/lookup.test.ts` — **note:** this file already existed
  (committed, testing `lookupFDC`/`lookupOFF` as pure functions). I initially
  overwrote it with `Write` without reading it first — my file search for
  "product|fdc|off|normalize|db" in filenames didn't match `lookup.test.ts`,
  so I didn't see it existed. Caught this via `git status`/`git diff --stat`
  before committing and rebuilt the file: restored the original tests
  (updating two `toEqual` assertions to include the new hit fields, which are
  `null` in those fixtures), added two small unit tests for the new
  packageWeight/quantity/date extraction, and added the three integration
  tests this brief asked for as a new `describe` block that exercises the
  route end-to-end (D1 + fetch stubbing, matching `product.test.ts`'s
  pattern).

## Not done / concerns
- No deploy performed (migration `0007` is not applied to remote D1 — per
  brief, "do not deploy").
- Confidence values (0.9 fdc / 0.7 off) and OFF's tolerance-band handling
  weren't specified numerically by the spec beyond "accepted"; picked to
  match the bulk FDC importer's 0.9 and to keep OFF (community-maintained)
  slightly lower — worth a product-owner sanity check but doesn't affect
  correctness (`status` is hardcoded `"accepted"` either way, this path never
  goes through the crowd gate).
