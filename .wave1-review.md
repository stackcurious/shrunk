## Verified clean (no action)

- **§2 rows implemented correctly:** shrink (alternatives primary, Watch · Share secondary);
  single snapshot ("No shrink on record", size fact line, `Watch — we'll alert you if it shrinks`
  primary, alternatives + "Snap the label to confirm" secondary); no size ("We don't know this
  size yet", "Snap the label to start tracking" primary, alternatives secondary); not found
  (unchanged, `ResultView.swift:519`).
- **`.needsLabel` before `.paywall`** (`ResultViewModel.swift:69-74`) matches the §2 ruling; pinned
  by `test_noCurrentSizeAndNotPro_isNeedsLabelNotPaywall`.
- **All four `WatchOutcome` branches give feedback** (`ResultView.swift:459-497`): `.watch` →
  success toast + `.success` haptic; throw → `errorDescription` toast + `.error` haptic +
  `toastIsError` restyles the Toast; `.paywall` → `ProPaywallView` sheet; `.needsLabel` →
  `LabelCaptureView`. No silent `return`s remain (rule 4).
- **Watch state restored on re-open** via `WatchlistService.fetch(barcode:)` seeding `isWatched`.
- **Kroger attribution preserved.** `sizeRecord(from:)` keeps `source: "kroger"` through adoption
  (pinned by `test_noObservations_withALiveSize_adoptsItAsTheCurrentSize`), and
  `ShrinkRecord.priceIsFromStoreSnapshot` is untouched — the cost/oz card's attribution gate
  (`ResultView.swift:334`) and `ShrinkAlert.newShrink(from product:)`'s `currentPrice` gate still
  key off a real `price_snapshots` row, so curated `trending.json` prices are still never labelled
  Kroger.
- **No alert regressions.** `recordScannedShrink` (`WatchlistService.swift:81-86`) still opens with
  `guard record.verdict.isShrink`; `.insufficientData` is not a shrink, so the new single-snapshot
  and adopted-size records file nothing. The `prebake == nil` gate at `ResultView.swift:53` is
  untouched, so curated Browse cards still cannot file.
- **`previousSize` → nil is contained.** Only the `sameKind.count < 2` branch changed; all six
  consumers (`ResultView:247,564`, `ShareCardView:100,116`, `BrowseView:227,304`,
  `ShrinkAlert:108-109,136-137`) already use `if let` / optional chaining, and both
  `ShrinkAlert.newShrink` factories are only reached behind `verdict.isShrink`.
  `comparisonRow`'s `else if let curr` branch now correctly draws "CURRENT SIZE" instead of a
  Then→Now row comparing a size with itself.
- **Cost-per-ounce math is unit-consistent.** `ShrinkDetector.costPerUnit(price:size:)`
  (`ShrinkDetector.swift:146-152`) divides by `normalize(size).quantity`, the same oz-equivalent
  space as `costPerOunce(price:quantity:unitKind:)` used by `AlternativesEngine` and
  `LivePricePanel`. Pinned by `test_singleObservation_normalizesTheUnitBeforePricing`
  (`1.89 / (946.353 * 0.033814)`).
- **No mass-vs-volume comparison.** `AlternativesEngine.storeAlternatives` filters
  `$0.unitKind == scannedKind` and skips the store search entirely when the kind is `unknown`;
  `cheapestAlternative` further restricts to `.source == .store` (curated rows carry
  `costPerUnit: nil`), so nothing numerically incomparable can reach the callout. The VM's
  re-read of the post-adoption record before `loadAlternatives`
  (`ResultViewModel.swift:130, 155-158`) is what makes that filter work at all on an adopted size.
- **Tests assert behaviour.** Records are built by running the real `ShrinkDetector` rather than
  hand-constructed, preconditions are asserted separately from the outcome, the precedence pair is
  pinned deliberately, and `test_liveSizeIsIgnoredWhenTheProductAlreadyHasAnObservation` /
  `test_liveSizeOfZeroIsNotAdopted` are genuine negative cases. No `as!` anywhere in the diff, no
  `print` / `TODO` / `FIXME` / debug strings.
- **UX copy** matches the §2 table verbatim for the rows that were implemented, including the
  watch toast ("Watching ‹name› — we'll alert you if it shrinks or its price per oz jumps") and the
  failure toast ("We need this product's size first — snap the label to start tracking it.").
