## 1. The two residual fixes (plus the dead `.unchanged` branch)

### 1.1 Share could draw a Then→Now the screen refuses to draw

`ResultView.swift:245` gated the Share button on `previousSize != nil` alone.
Since the S13 fix that set also contains the two `.insufficientData` states — the
zero-quantity guard (`ShrinkDetector.swift:88-101`) and the cross-source
plausibility clamp (`:111-127`) both return `.insufficientData` **with** a
`previousSize`. `ShareCardView.swift:106,121` had no verdict guard at all. So a
screen reading "No shrink on record" could still produce a shareable PNG saying
*"They took 946.4 ml / from 0ml → 946.4ml"*.

Fixed with one predicate, asked by both places:

```swift
// Shrunk/Features/Result/ShareCardView.swift
static func canShare(record: ShrinkRecord) -> Bool {
    record.verdict != .insufficientData
        && record.previousSize != nil
        && record.currentSize != nil
}
```

- `ResultView.swift:245` → `if ShareCardRenderer.canShare(record: record)`
- `ShareCardView.swift:106,121` → the `tookString` / `fromTo` closures both take
  `comparable = canShare(record:)` as their first condition, so even a
  directly-constructed renderer call falls back to "Tracked by Shrunk" /
  "first scan" rather than an untrustworthy pair.

**One deliberate deviation from the brief**, called out for review: the brief
said gate on `isShrink || .grew`. I gated on `verdict != .insufficientData`
instead. The two are *identical today* — `.unchanged` is unreachable from
`ShrinkDetector.analyze` (see §1.3) — but spec §2 lists Share on the
"Unchanged / grew" row, and `WatchedProduct` and the alert models still carry
`.unchanged`. Writing it as "is the verdict real" makes the gate **byte-identical
to `ResultView.comparisonRow`'s own gate**, which is what the review actually
asked for ("the two gates should agree"), and it cannot silently drop Share if
that band ever becomes reachable again. `test_unchangedStaysShareablePerSpec-
Section2` pins the decision. Say the word if you want the narrower literal form.

### 1.4 The unreachable `.unchanged` branch — kept, commented

`ResultView.bannerSubline`'s `case .unchanged:` ("Same size since ‹YYYY›") is
dead after `f42766d`: `ShrinkDetector` now compares the last two *size runs*, and
adjacent runs differ by more than `sameSizeTolerance` by construction, so
`percentChange` can never land in the ±1 % band. **Kept, not deleted** — the
`switch` over `ShrinkVerdict` must be exhaustive, so deleting the case only means
folding its copy into another branch and losing §2's wording. It now carries an
eight-line comment saying it is unreachable from `analyze`, why, and that
`.unchanged` is still live in `WatchedProduct` / `ShrinkAlert`.

Recorded in the spec, `docs/superpowers/specs/2026-08-27-scan-value-and-native-ui.md`
§2, immediately under the state table:

> Since size runs landed (`ShrinkDetector` compares the last two *runs*, not the
> last two observations), the "Unchanged" half of row 2 is unreachable — a size
> that held collapses into one run and reports the single-snapshot state instead;
> the branch is kept in `ResultView.bannerSubline` for switch exhaustiveness and
> because the alert models still carry `.unchanged`. Share is gated by
> `ShareCardRenderer.canShare(record:)`, the same predicate `comparisonRow` uses,
> so the shared PNG can never draw a Then→Now the screen refused to.
