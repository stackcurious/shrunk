## Screens done

**Chrome**
- `ShrunkApp.swift` — standard `TabView`, SF Symbols, Scanner still the default tab.
  Watchlist's symbol is now `eye` (it was a second `bell.badge` beside Alerts).
  The window scheme is `.dark` only on the Scanner tab and `nil` (follow system)
  everywhere else — that one line is what turns dark mode on app-wide.
- `Core/Theme/ShrunkTheme.swift` — `paper/ink/mist/smoke/surface/border/borderSoft`
  now resolve to semantic system colours; brand and verdict washes became
  light/dark pairs through a new `Color.dynamic(light:dark:)`. Brand red
  `#E24B4A` is untouched and still the app `.tint`. Nothing was deleted or
  renamed, so `Features/Result/*` keeps compiling; the file also gains a
  `groupedCard()` modifier used by the restyled screens.
- `Core/Components/*` — `ShrunkButton` → `.borderedProminent` / `.bordered` /
  `.borderless` at `.controlSize(.large)`, with `.sensoryFeedback(.impact)`
  replacing the hand-fired `UIImpactFeedbackGenerator`; `EmptyStateView` →
  `ContentUnavailableView`; `StatBox` → GroupBox-style cell with
  `.monospacedDigit()`; `Toast` → `.regularMaterial` capsule; `ShrunkPageHeader`
  kept but reduced to system large-title type (no tab uses it any more);
  `ProBadge`, `ShrinkMeter`, `ProductImage`, `ProductThumb` lost their tracking,
  hand-set point sizes and hairline borders.

**Tabs**
- Scanner — dark camera chrome kept; wordmark/status pill/recent chips are system
  text styles over `.ultraThinMaterial`; barcodes use `.monospacedDigit()`;
  permission fallback is a `ContentUnavailableView`.
- Browse + CategoryDetail — `NavigationStack` large title, cards on
  `secondarySystemGroupedBackground`, no borders or shadows; Hall of shame is one
  card with dividers; empty/error states are `ContentUnavailableView`.
- Watchlist — real `List(.insetGrouped)`. Side effect worth knowing: the
  swipe-to-remove action now actually works, because `swipeActions` only ever
  applied inside a `List` and the rows used to sit in a `VStack`.
- Alerts — `List(.insetGrouped)`, filter chips → segmented `Picker` in the section
  header, savings hero → an ordinary row.
- Settings — `List` of `Section`s with real header/footer text; the uppercase
  tracked labels and hand-drawn cards are gone. Every string is unchanged.

**Sheets**
- `NotificationPreferencesView` — a `Form` of `Toggle`s, `Picker`s and a labelled
  `Slider`.
- `ProPaywallView` — copy, prices, both legal links and the App Review
  auto-renewal disclosure are byte-for-byte unchanged; only type, controls and
  layout moved. Now `.presentationDetents([.medium, .large])` opening large, so
  the disclosure block stays reachable (and the screenshot test still finds it).
- `StorePickerView` — `.searchable` list in the sheet. The onboarding embed has no
  `NavigationStack` to host a search bar, so it keeps a numeric ZIP field in its
  own `Section`; both share the same result rows.
- Onboarding, savings dashboard, alternatives, `LabelCaptureView`, and
  `ContributeConfirmSheet` follow the same rules. `ContributeConfirmSheet` was not
  on the dispatch list but is the sheet `LabelCaptureView` presents and appears in
  App Store shot 04, so it was restyled for coherence (its "Check the size" text,
  which the test asserts, is unchanged).

Nothing in `Features/Result/*`, `Services/ShrinkDetector.swift`,
`Services/WatchlistService.swift` or `Models/*` was touched. No copy, price,
disclosure or behaviour changed anywhere; `-ui-testing` overrides still work
(all six screenshot tests pass unmodified).
